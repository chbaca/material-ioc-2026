7.1

Fundamentos de Sistemas Operativos

Qué es un sistema operativo según quién lo mire, y qué piezas lo componen por dentro.

7.1.1 — Definición

Concepto clásico

Un sistema operativo es un software de sistema: un conjunto de programas destinado a muchas tareas, entre las que destaca la administración eficaz de los recursos de la computadora (Wikipedia).

Vista del usuario

"Un conjunto de programas y funciones que controlan el funcionamiento del hardware ocultando sus detalles, ofreciendo al usuario una vía sencilla y flexible de acceso a la computadora".

Vista del administrador

El administrador de los recursos ofrecidos por el hardware para lograr un rendimiento eficaz: procesador, memoria, entrada/salida e información (A. Tanenbaum, Sistemas Operativos Modernos).

7.1.2 — Componentes de un sistema operativo

Por lo general, un sistema operativo tiene 4 componentes fundamentales:

Administrador o gestor del procesador

Administrador de memoria

Sistema de archivos

Administrador de E/S

Y otros componentes opcionales: intérprete de comandos (shell), gestor de almacenamiento secundario, sistema de protección, sistema de comunicaciones, y utilitarios internos.

Administrador del procesador

  • Crear y destruir procesos
  • Planificar procesos
  • Parar y reanudar procesos
  • Ofrecer mecanismos de comunicación y sincronización entre ellos

Administrador de memoria

  • Decidir qué procesos se cargan en memoria cuando hay espacio
  • Registrar el espacio asignado y el espacio libre
  • Asignar y reclamar espacio cuando sea necesario

Sistema de archivos

  • Construir y eliminar archivos y directorios
  • Manipular archivos y directorios
  • Corresponder archivos con unidades de almacenamiento
  • Realizar copias de seguridad

Administrador de E/S

Un sistema de almacenamiento temporal (caché) y una interfaz de drivers de dispositivos. Gestiona el buffer de E/S y sirve las interrupciones de los dispositivos.

Componentes opcionales

Sistema de protección

Controla el acceso de programas o usuarios a los recursos: distingue uso autorizado/no autorizado, especifica controles de seguridad y fuerza su cumplimiento.

Sistema de comunicaciones

Controla el envío/recepción de información por las interfaces de red, creando y manteniendo puntos y conexiones virtuales entre aplicaciones locales y remotas.

Intérprete de comandos (Shell)

Permite la comunicación del usuario con el SO mediante órdenes escritas, con sintaxis definida, y ofrece un lenguaje de órdenes para scripts. El Bourne Shell fue el usado en las primeras versiones de Unix y se convirtió en estándar.

Gestor de almacenamiento secundario

Planifica discos y dispositivos de almacenamiento, gestiona el espacio libre, asigna almacenamiento y verifica el orden de guardado de los datos.

Utilitarios internos: se suministran con el SO pero estrictamente no forman parte de él. Ofrecen manipulación de archivos, información del estado del sistema, soporte a lenguajes de programación y comunicaciones.
7.1.3

Tipos de Sistemas Operativos por su estructura

Cuatro modelos, organizados por orden de surgimiento y evolución.

Estructura monolítica

Es la estructura de los primeros sistemas operativos: un solo programa, conformado por un conjunto de rutinas entrelazadas que podían llamarse entre sí, comunicándose a través de parámetros. Carecían de protecciones y privilegios al entrar a rutinas que manejaban memoria, disco, etc. En su evolución apareció una estructura mínima con un procedimiento principal que invocaba a otros.

Ejemplos: CP/M, MS-DOS en sus primeras versiones, Mac OS hasta la versión 8.0.

Estructura por capas o jerárquica

A medida que crecían las necesidades, se organizó el software en niveles o anillos: el nivel N solo presta servicios al nivel N+1, y puede solicitar servicios al nivel N−1. Una de las capas es el kernel o núcleo, que ofrece servicios a la capa superior. Algunas funciones (como la E/S) pueden sacarse del kernel y llevarse a otros niveles.

Linux y THE (diseñado con fines didácticos) usan esta estructura.

Android también la usa. Mac OS X es un sistema modular de 4 capas, cuyo núcleo está conformado por Mach y BSD.

Máquina virtual

Un tipo de sistema operativo que, si bien controla todo el hardware de la máquina, ofrece la posibilidad de crear y utilizar máquinas virtuales, idénticas a la subyacente pero con diferentes sistemas operativos instalados. Cada usuario conectado tiene la sensación de contar con su propia computadora real, aunque en realidad se trata de un sistema operativo anfitrión que ofrece esa posibilidad de uso.

Su kernel se llama Monitor de la Máquina Virtual, que se ejecuta sobre el hardware generando varias máquinas virtuales (multiprogramación). Ejemplo histórico: VM/370, la primera máquina virtual. Hoy ha resurgido bajo el nombre hipervisor, organizado en dos niveles:

Hipervisor tipo I

Se ejecuta directamente sobre el hardware, sin un sistema operativo anfitrión de por medio.

Hipervisor tipo II

Se ejecuta como una aplicación dentro de un sistema operativo anfitrión ya instalado.

Ejemplos de hipervisores actuales: JVM (Java), VMware, VirtualBox, PC Virtual, entre otros. La JVM (Java Virtual Machine) es un caso particular: el compilador de Java genera código para la JVM, que se ejecuta mediante un intérprete — esto permite enviar ese código por Internet a cualquier computadora con intérprete de JVM y ejecutarlo allí.

Cliente-servidor

Modelo de aplicación distribuida donde las tareas se reparten entre servidores (proveedores de recursos o servicios) y clientes (demandantes). Un cliente realiza peticiones a un programa servidor, que le da respuesta. Aplicable en una sola computadora, aunque resulta más ventajoso en un sistema operativo multiusuario distribuido en red.

Ejemplos: Windows NT, Mach.
7.1.5

Kernel, modos de ejecución e interfaces

El núcleo del sistema, sus dos niveles de privilegio, y cómo se presenta al usuario final.

El kernel es el código que administra los recursos, ejecuta las aplicaciones, controla el hardware y establece prioridades. Se ejecuta al mayor nivel de privilegio (acceso irrestricto a los dispositivos físicos), administra la memoria asignando espacios de direcciones privados a cada proceso, establece el privilegio de lectura/escritura, e impide el acceso no controlado de otros procesos. Sus servicios se acceden mediante llamadas al sistema.

Modo supervisor

Modo en el que se ejecuta el kernel: acceso total a las instrucciones de la CPU. Un fallo de programación aquí puede colgar el sistema operativo. La CPU siempre arranca en este modo.

Modo usuario

Las aplicaciones (y las bibliotecas del SO que no pertenecen al kernel) se ejecutan con privilegios restringidos, accediendo solo a un subconjunto de instrucciones.

7.1.6 — Sistemas operativos más conocidos

Computadoras personales

Mac OS X, Microsoft Windows, GNU/Linux, Unix, Solaris, Debian, Ubuntu, Mandriva, Sabayon, Fedora, Linpus Linux, Haiku (BeOS), FreeBSD, OpenBSD, Google Chrome OS.

Dispositivos móviles

Android, iOS, Bada, BlackBerry OS, Windows Phone, Symbian OS, HP webOS, Firefox OS, Ubuntu Phone OS.

Tipos de interfaz

Línea de comandos: órdenes por teclado. Interfaz gráfica: ventanas, botones y menús para seleccionar operaciones.

7.2

Sistemas operativos libres y propietarios

Dos filosofías de licenciamiento, y la historia que dio origen al software libre.

7.2.1 — Software propietario

También llamado privativo, de código cerrado o no libre: cualquier programa donde el usuario tiene limitaciones para usarlo, modificarlo o redistribuirlo, reservando esos derechos para el autor. Ejemplos: MS-DOS, Windows en todas sus versiones, macOS, entre otros.

7.2.2 — Software libre

Es la denominación del software que respeta la libertad de los usuarios sobre el producto adquirido: una vez obtenido, puede ser usado, copiado, estudiado, modificado y redistribuido libremente. Según la Free Software Foundation, se trata de 4 libertades:

  1. Libertad 0: usar el programa con cualquier propósito.
  2. Libertad 1: estudiar el funcionamiento del programa y adaptarlo a las necesidades propias (requiere acceso al código fuente).
  3. Libertad 2: distribuir copias, para ayudar a otros.
  4. Libertad 3: mejorar el programa y hacer públicas las mejoras, en beneficio de toda la comunidad (también requiere el código fuente).
La historia de la impresora de Stallman: en el laboratorio donde trabajaba Richard Stallman, una impresora donada por una empresa se atascaba con frecuencia sin avisar a la red. Stallman quiso agregar un aviso automático, pero necesitaba el código fuente del driver — la empresa se lo negó. Frente a esa disyuntiva (aceptar software propietario con acuerdos de no revelación, o buscar otra vía), en 1984 comenzó el proyecto GNU, y un año después fundó la Free Software Foundation (FSF), introduciendo el concepto de copyleft para otorgar libertad a los usuarios y restringir la apropiación del software.

Código abierto u Open Source

Surgió en 1998 con Eric S. Raymond y Bruce Perens, fundadores de la Open Source Initiative (OSI), buscando resaltar los beneficios prácticos de compartir el código fuente frente a las grandes empresas de tecnología. La idea: al compartir el código, el programa evoluciona más rápido — los programadores lo leen, modifican y redistribuyen, corrigiendo errores a mayor velocidad que en el desarrollo cerrado.

Software libre

Pone énfasis en los aspectos éticos: el software propietario, al no poder compartirse, es "antiético" porque prohibir compartir entre seres humanos va contra el sentido común.

Código abierto

Pone la excelencia técnica como objetivo prioritario, usando la compartición del código como un medio para alcanzarla, no como un fin ético en sí mismo.

7.3

Estudio de caso: el sistema operativo libre GNU/Linux

Del reemplazo de un sistema académico a la base de las supercomputadoras del mundo.

GNU/Linux es uno de los ejemplos más prominentes de software libre: su código puede usarse, modificarse y redistribuirse bajo los términos de la GPL (General Public License) y otras licencias libres. "GNU/Linux" es el nombre del sistema operativo completo: Linux es el nombre del núcleo (kernel), similar a Unix, y el resto (la interacción entre hardware y usuario) se maneja con las herramientas del proyecto GNU y entornos de escritorio como GNOME, que también forma parte del proyecto GNU.

Datos de uso: GNU/Linux es utilizado por el 78% de los 500 principales servidores del mundo, y por el 89% de las 500 mayores supercomputadoras. En computadoras de escritorio su porcentaje es menor.

¿Por qué las supercomputadoras actuales usan Linux?

Naturaleza modular

Una instalación común está hecha de pequeños módulos, cada uno con una tarea distinta — es más fácil modificar una tarea sin afectar las demás.

Naturaleza genérica del kernel

El mismo código fuente puede correr en supercomputadoras y en pequeños dispositivos, sin grandes cambios al kernel.

Escalabilidad

Linux soporta grandes cargas de forma sencilla: capacidad de un servidor de adaptarse a cargas altas.

Código abierto

Linux es por completo código abierto, lo que permite personalizaciones a medida.

Soporte de la comunidad

Cuenta con una comunidad inmensa que da soporte, algo que ningún otro sistema tiene en esa escala.

Costo y reinicios

Totalmente gratuito, y permite probar configuraciones de red "en caliente" sin reiniciar el sistema.

Historia de sus orígenes: el proyecto GNU se inició en 1983 por Richard Stallman, con el objetivo de desarrollar un sistema operativo Unix completo y libre. En 1991, Linus Torvalds (estudiando Ingeniería Informática en la Universidad de Helsinki) empezó a trabajar en un reemplazo no comercial de MINIX. Cuando presentó la primera versión de Linux en 1992, el proyecto GNU ya tenía herramientas fundamentales (intérprete de comandos, biblioteca C, compilador), pero su propio kernel (llamado Hurd) aún no estaba maduro — por eso se adoptó Linux, llenando el espacio final que le faltaba al sistema GNU.

7.3.1 — Interfaces y entornos de escritorio

GNU/Linux funciona tanto en entorno gráfico como en modo consola (esta última, común en distribuciones para servidores). Los entornos de escritorio más populares son: GNOME, KDE SC, LXDE y Xfce. En dispositivos móviles, Android funciona sobre el núcleo Linux, pero no usa las herramientas GNU.

7.3.2 — Empresas que apoyan a GNU/Linux

Intel, Google, IBM, AMD, Sun Microsystems, Dell, Lenovo, Asus, HP, SGI, Fujitsu, Oracle, Novell, VIA Technologies y Red Hat, entre otras, colaboran trabajando en el núcleo, ofreciendo soluciones de software o preinstalando el sistema. También hay respaldo de software comercial: Nero, Java, Google Earth, Adobe Reader y Flash, Real Player, Yahoo! Messenger, todos disponibles para GNU/Linux.

7.3.3 — Distribuciones de Linux

Una distribución (distro) es un paquete de software basado en el núcleo Linux, que incluye bibliotecas y herramientas GNU, el sistema de ventanas X Window, y otro software (procesadores de texto, hojas de cálculo, herramientas administrativas) según el público al que apunta.

Con soporte comercial

Fedora (Red Hat), openSUSE (Novell), Ubuntu (Canonical), Mandriva.

Mantenidas por la comunidad

Debian, Gentoo.

Independientes

Slackware (sin relación con empresa o comunidad alguna).

Un caso cercano: la distribución Ututo fue desarrollada por docentes de la Universidad Nacional de Salta.

7.3.4 — Dispositivos en Linux

Para Linux, todo es un archivo: discos duros, CD-ROMs, memorias USB, puertos seriales y paralelos, módems, terminales — todos representados bajo el directorio /dev, identificados con dos o tres letras y numerados secuencialmente desde 0.

Identificador Tipo de dispositivo
hd Discos duros IDE y dispositivos IDE como CD-ROMs
sd Discos duros SCSI / SATA
scd CD-ROM SCSI
lp Puertos paralelos
tty Terminales o consolas
ttyS Puertos seriales
eth Tarjetas o interfaces de red Ethernet
Canal IDE En Linux En Windows
Maestro primario /dev/hda C:
Esclavo primario /dev/hdb D:
Maestro secundario /dev/hdc E:
Esclavo secundario /dev/hdd F:

Es común encontrar enlaces simbólicos, como /dev/cdrom apuntando al verdadero archivo de dispositivo (por ejemplo /dev/hdc), o /dev/modem apuntando a /dev/ttyS0. En síntesis: en GNU/Linux y Unix, discos, particiones, teclado, mouse y tarjeta de audio están todos mapeados en el sistema de archivos, simplificando la interfaz de acceso.

7.3.5 — Particiones en Linux

Un disco puede tener como mínimo 1 y como máximo 4 particiones primarias; las particiones lógicas comienzan a partir de la 5. Para instalar Linux se necesitan como mínimo dos particiones: la principal (donde se instala el SO) y una partición swap (intercambio de memoria virtual, usada cuando la RAM es insuficiente — su tamaño suele ser el doble de la RAM).

7.3.6 — Montaje de recursos

Tras crear las particiones, se debe crear como mínimo el punto de montaje del directorio raíz (/). Linux usa una estructura jerarquizada en árbol invertido, donde todo se trata como un archivo y debe estar "montado" dentro de esa estructura para poder accederse. También se puede crear otro punto de montaje, como /home, en una partición diferente: así, si se formatea la partición del sistema, los datos de /home quedan a salvo.

7.3.7 — Sistema de archivos de GNU/Linux

Existen distintos sistemas de archivos para Linux: ext2, ext3, ext4, ReiserFS, entre otros. Tras formatear, queda la siguiente estructura de directorios:

Directorio Contenido
/ Directorio raíz. Punto de partida de todo archivo y directorio. Solo el usuario root puede escribir aquí.
/bin Ejecutables de Linux (cp, mv, cat, etc.)
/etc Archivos de configuración instalados y scripts de inicio
/home Un directorio por cada usuario, con sus archivos y configuraciones personales
/sbin Ejecutables de administración: mount, umount, shutdown, etc.
/media Montaje de unidades extraíbles: USB, disqueteras, CD/DVD
/tmp Archivos temporales, se eliminan en cada inicio
/boot Archivos de arranque: GRUB/LILO y el propio kernel
/lib Bibliotecas del sistema, módulos y drivers
/usr Ejecutables de aplicaciones (/usr/bin), cabeceras C/C++ (/usr/include), código fuente del kernel (/usr/src), entre otros
/var Buffer de impresión, logs del sistema (/var/log), correos (/var/mail), archivos temporales (/var/tmp)

7.3.5 (bis) — Permisos

En Linux todos los archivos pertenecen obligatoriamente a un usuario y a un grupo. Existen tres tipos de permiso: lectura (ver contenido de un archivo, o listar el de una carpeta), escritura (modificar o borrar) y ejecución (solo aplicaciones y scripts). Los permisos se otorgan a tres grupos: el usuario propietario, el grupo propietario, y el resto de los usuarios del sistema. Con ls -l se visualizan el propietario, el grupo y los permisos de cada archivo.

7.4

Distribución Huayra

El sistema operativo libre de Conectar Igualdad, pensado para el aula.

Huayra es el sistema operativo libre desarrollado por Conectar Igualdad (ANSES) para las netbooks de estudiantes y docentes, con aplicaciones educativas y herramientas para el aula. Está basado en Debian (más de 37 mil paquetes de software, soporte para más de 10 arquitecturas de hardware), con una gran comunidad de voluntarios y licencia mayormente GNU GPL.

7.4.1 — Particiones en Huayra

Huayra toma su estructura de directorios del estándar FHS (Filesystem Hierarchy Standard). Las netbooks de Conectar Igualdad vienen con doble booteo, por lo que disponen de 5 particiones:

Partición Huayra — sistema operativo Linux

Partición Windows — el otro sistema operativo

Partición DATOS — accesible desde ambos SO

Partición de recuperación — configuración original de fábrica

Partición swap — espacio de intercambio de memoria

7.4.2 — Partición Huayra: archivos y directorios

Contiene todos los directorios y archivos del sistema, y muchos archivos personales (imágenes, fotos, música). El directorio /home guarda la carpeta personal de cada usuario — inicialmente solo /home/alumno — junto con configuraciones ocultas de las aplicaciones, por lo que es clave incluirlo en cualquier backup.

7.4.3 — Partición DATOS

Contiene contenidos accesibles desde cualquiera de los dos sistemas operativos (libros, videos), incluida la carpeta /datos/mis cosas. De hecho, /home/alumno es en realidad un link a ese directorio de la partición DATOS. Desde Huayra se puede acceder a archivos guardados en Windows usando los programas propios de Huayra (ej: un .doc se abre con OpenOffice).

7.4.4 y 7.4.5 — Partición Windows y montaje

Los archivos de Windows se almacenan en su propia partición, con una estructura de directorios que varía según la versión. Para acceder a DATOS o WINDOWS desde Huayra, simplemente se hace clic en la partición deseada, ingresando la contraseña "alumno" la primera vez — o bien usando el comando mount desde una consola.

7.4.6 — Algunas aplicaciones de Huayra

Arduino IDE — programación de microcontroladores (placas con Atmel AVR)

Icaro y Pilas — robótica educativa y videojuegos con Python

Dia — diagramas entidad-relación, UML, de flujo y de redes

Etoys — entorno de desarrollo para Smalltalk

Euler e iPython — cálculo numérico y programación

Gambas3 — lenguaje libre derivado de BASIC

Celestia — simulación del espacio en 3D

Dr. Geo y Geogebra — geometría interactiva y matemática

CDPedia — Wikipedia en español sin conexión

Blender — diseño y animación 3D

Orca — lector/magnificador de pantalla para accesibilidad visual

7.6

Instalación de sistemas operativos

De la imagen ISO al pendrive booteable, y de ahí a la instalación en el disco.

7.6.1 — Software para crear pendrives booteables

LiLi USB Creator

Libre y de código abierto. Solo en Windows (10, 8.1, 7, Vista, XP).

UNetbootin

Soporta las principales distros de Linux; permite cargar utilidades como Parted Magic. Funciona en Windows, Linux y Mac.

Rufus

Muy veloz, libre y de código abierto. Instala Windows o Linux. Solo en Windows.

Yumi

Crea discos de arranque multiboot (varios SO) y permite instalar cualquier imagen ISO.

7.6.2 — Instalación del sistema Huayra

Recursos necesarios: imagen ISO (desde huayra.conectarigualdad.gob.ar), UNetbootin, y un pendrive de 3 GB o más. Recomendaciones: hacer backup, desfragmentar el disco, formatear el pendrive.

Crear el pendrive booteable

  1. Descargar Huayra (imagen ISO) y UNetbootin.
  2. Conectar el pendrive y ejecutar UNetbootin.
  3. Seleccionar "diskimage" y buscar la carpeta donde está la ISO descargada. Luego, OK.
  4. Seleccionar el pendrive de destino y esperar a que se complete el proceso.

Instalar Huayra como sistema operativo único

  1. Conectar el pendrive en la PC.
  2. Arrancar el equipo, ingresar al setup y configurar el arranque desde el pendrive.
  3. Elegir si la PC tendrá un solo SO (Huayra) o si se mantendrá el sistema existente, agregando a Huayra como otra opción de arranque.
  4. Para la opción de SO único: seleccionar "Instalar Huayra en tu disco" en el menú.
  5. Seleccionar la configuración de idioma del teclado.
  6. Huayra detecta los discos y comienza el particionado: elegir "Guiado — utilizar todo el disco" para instalar en todo el disco.
  7. Elegir el disco a particionar.
  8. Elegir el esquema de particionado (se recomienda "Todos los ficheros en una partición"; si se planea instalar otras distros después, conviene "separar particiones").
  9. Confirmar "Finalizar el particionado y escribir los cambios en el disco".
  10. Comienza el particionado y la instalación (demora unos minutos).
  11. En el menú de configuración de GRUB, simplemente continuar — el instalador toma la configuración correcta automáticamente.
  12. Finalizar la instalación, retirar el pendrive y reiniciar la PC.

Instalar Huayra manteniendo el sistema operativo anterior (dual boot)

  1. Iniciar la PC con el pendrive booteable, configurando el dispositivo de arranque en el setup.
  2. Seleccionar la opción "Huayra (Live)" para cargarlo directamente desde el pendrive.
  3. Una vez cargado Huayra, ir a Sistema → Administración → GParted para particionar el disco.
  4. Clic derecho sobre la partición grande disponible (ej: una partición NTFS) y seleccionar "Redimensionar/mover". Se recomienda un espacio mínimo de 20 GB para Huayra — se reduce la partición existente para dejar espacio libre.
  5. Aplicar los cambios.
  6. Acceder al menú superior izquierdo y elegir "Huayra / Instalar".
  7. Seleccionar la configuración de idioma del teclado.
  8. En el particionado, elegir "Guiado — utilizar el espacio libre contiguo más grande".
  9. Los pasos siguientes son idénticos a la instalación como sistema único.
7.5

Sistemas de archivos

Cómo se organiza, dentro de cada partición, el espacio donde viven los archivos.

Un sistema de archivos se encarga de la asignación de espacio a los archivos, la administración del espacio libre y el acceso a los datos resguardados.

7.5.1 — Tipos de sistemas de archivos

De disco

Diseñado para almacenar archivos en una unidad de disco. Ejemplos: ext2/3/4, FAT, FAT32, exFAT, NTFS, HFS+, UFS, ZFS, entre muchos otros.

De red

Accede a archivos a través de una red de computadoras. Ejemplos: AFS, AppleShare, CIFS/SMB (redes Microsoft), NFS, Coda.

De propósito general

Casos especiales como procfs, devfs, tmpfs o el sistema de archivos swap, que organiza la partición de intercambio.

Sistemas de archivos más comunes, por sistema operativo

Sistema operativo Sistemas de archivos
MS-DOS / Windows 3.1 FAT
Windows 95 FAT, VFAT
Windows 98 FAT, VFAT, FAT32
Windows NT FAT, VFAT, NTFS, HPFS
Windows XP FAT, VFAT, FAT32, NTFS
Windows Vista / 7 FAT, FAT32, NTFS
Windows 8 / 10 NTFS, ReFS
OS/2 HPFS
Linux ext2, ext3, ext4, JFS, ReiserFS, XFS
Mac OS HFS, HFS+, APFS
Solaris UFS, ZFS

7.5.2 — Sistema de archivos FAT

FAT (File Allocation Table) es un sistema de Microsoft introducido en 1981 con las primeras PCs. Es una tabla que contiene el índice de los clusters del disco; se guardan dos copias de la FAT para proteger el volumen ante daños.

Un cluster (o unidad de asignación) es un agrupamiento de sectores contiguos: la mínima unidad de almacenamiento de un archivo en una partición. La FAT tiene una entrada por cada cluster, registrando los usados, libres y defectuosos. Cuando se crea un archivo, se registra su primer cluster, y desde ahí se encadenan los siguientes — lo que, por fragmentación, suele dejarlos distribuidos por toda la partición.

Ejemplo numérico: con clusters de 4 KB, un archivo "Informe1.doc" de 22 KB necesita 6 clusters. Supongamos que los asignados son: 6, 9, 3, 10, 5 y 12. La entrada del directorio para Informe1.doc guarda su cluster inicial (6); a partir de ahí, la tabla FAT encadena: cluster 6 → apunta a 9 → apunta a 3 → apunta a 10 → apunta a 5 → apunta a 12 → fin de archivo. Así, aunque el archivo esté "salpicado" por la zona de datos, el sistema puede reconstruir su contenido completo siguiendo la cadena.
Cluster N° Contenido de la entrada FAT
6 (inicio) → 9
9 → 3
3 → 10
10 → 5
5 → 12
12 fin de archivo

7.5.3 — VFAT

Usa la misma estructura de directorio, formato y tipo de partición que la FAT tradicional, pero suma la capacidad de almacenar nombres largos, mediante bloques de directorio adicionales llamados slots. Fue una implementación tipo "parche" para mantener compatibilidad con el software anterior.

7.5.4 — FAT32

Mejoras sobre FAT/VFAT

  • Admite unidades de hasta 2 TB
  • Clusters más chicos (4–8 KB): menos espacio desperdiciado
  • MBR ampliado con una copia de las estructuras críticas: más resistente a errores
  • Carpeta raíz como cadena de clusters ordinaria: sin límite de entradas, y ubicable en cualquier unidad

exFAT (7.5.5)

Sistema de Microsoft diseñado especialmente para unidades extraíbles como pendrives o memorias USB.

7.5.6 — HPFS

Presentado por Microsoft en 1989 junto al sistema operativo OS/2, para dar mejor acceso a discos duros grandes. Mantiene la organización de directorios de FAT, pero agrega ordenamiento automático por nombre, nombres de hasta 254 caracteres, y cambia la unidad de asignación de clusters a sectores físicos de 512 bytes. Organiza el almacenamiento en bandas de 8 MB, cada una con su propio mapa de bits. Incluye un superbloque (sector lógico 16) con un puntero al directorio raíz. Es compatible con Windows NT, Linux y FreeBSD.

7.5.7 — NTFS

NTFS (New Technology File System) es el sistema de Windows NT y sus sucesores (2000, XP, Vista, 7, 8, 10) — hoy el más común en equipos personales. Está basado en el HPFS de IBM/Microsoft, con influencias del HFS de Apple.

  • Permite definir el tamaño del cluster desde 512 bytes, independientemente del tamaño de la partición.
  • Usa un registro transaccional (journaling), que mejora la estabilidad registrando los cambios en un diario.
  • Su componente principal es la MFT (Master File Table): almacena nombre, directorio, ubicación física, tamaño, permisos y las cuatro marcas de tiempo (creación, modificación, último acceso y última actualización del registro MFT) de cada archivo. Incluye una copia de respaldo de sí misma. Las primeras 16 entradas están reservadas para registros especiales.
  • Almacena los nombres en Unicode (UTF-16) y organiza la estructura en árboles-B, acelerando el acceso y reduciendo la fragmentación.
Su diseño evita que el usuario tenga que ejecutar utilidades de reparación de disco. Su principal desventaja: necesita bastante espacio en disco para sí mismo. Como su código no fue liberado, mediante ingeniería inversa se desarrolló NTFS-3G, que da soporte de lectura y escritura en GNU/Linux, Solaris, macOS y BSD.

7.5.8 — Sistemas de archivos de CD/DVD

Antiguos

High Sierra (primer sistema para CD), ISO 9660 (estandarizado en 1984) y sus variantes Joliet (Microsoft), Romeo (Adaptec) y RockRidge (compatibilidad con UNIX); y HFS, específico de Macintosh.

Actuales

UDF (Universal Disk Format), sucesor de ISO 9660, usado en DVD (v1.02), Blu-ray y HD-DVD (v2.50/2.60); y LFS, el nombre de UDF 2.5 en Windows Vista.

7.5.9 — Sistemas de archivos de Linux

Ext2 → Ext3 → Ext4

Ext2 fue el primero diseñado para Linux; Ext3 lo mejoró; Ext4 (mejora de Ext3) permite sistemas de hasta 1 EB, archivos de hasta 16 TB, directorios ilimitados (frente a los 32.000 de Ext3), mayor velocidad de creación/borrado y soporte extent (reserva de áreas contiguas para reducir la fragmentación).

ReiserFS y Linux-swap

ReiserFS fue diseñado por la empresa Namesys (liderada por Hans Reiser), soportado por Linux y otros sistemas. Linux-swap es el sistema de archivos usado para la partición de intercambio.
